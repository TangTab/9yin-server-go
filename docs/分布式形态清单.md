## 二、:15000 UDP 注册通道（核心增量）

官方 FsSoloLister 用**双 UDP 广播口**做内网服务发现（终局细节见
FsSoloLister全解与Go复刻.md §四）：

- 本地环回口（仅 InnerAddr≠127.0.0.1 时建，bind 127.0.0.1）+ 配置口
  `[Inner] Addr:[Broadcast] Port`（默认 15000，跨机）——**本地口收到的
  合法包原样中继转发到广播目标**（同机定向 → 跨机可达）
- 所有 UDP 包过 **identity 校验**（CReactor::ProcessBroad：包首
  connector id 必须匹配本口登记值，不符丢弃并记日志）——防串口

### 注册报文（RecvEntryServerInfo / RecvWorldServerInfo 同构）

报文头（+0 kind 0=world/1=entry、+4 魔数、+0x1C 分区门）与两种包长
（solo 系 **0x84**/0x48、大写系 0x78/0x48，魔数 0x3001/0x300——**两系
不互通**）。entry payload 布局（逆向实证，偏移）：

```
+0x20  int   server_id      服实例 id（FindServer 键；entry 不建服，world 包建）
+0x24  int   line_index     线路槽下标，必须 < 0x10（每服 16 槽）
+0x28  int   line_id        线路 id（**IDC>0 时**应答只回匹配槽——勘误，
                            非 ListerId；两系同字段）
+0x2c  char  ip[16]         通告地址（CopyString 定长拷贝）
+0x3c  int   port           通告端口
+0x40  int   max            该线上限
+0x44  int   cur            当前在线
```

world 包另有 `+0x08 ip[16] / +0x24 wchar name / +0x6C max / +0x70 cur /
+0x74 visible / +0x78 recommend`（recommend>10 直通 busy，solo 独有）。

### 服务端内部表（server_t / line_t 布局，solo 系终局）

```
server_t（0x4E8；大写系为 0x4FC 且头带 CRITICAL_SECTION）:
  +0x00  byte  visible（=world 包 +0x74≠0；应答可见门兼有效位）
  +0x01  byte  from_world
  +0x04  int   server_id（FindServer 键）
  +0x08  int   world_latch（world 心跳闩锁）
  +0x0c  int   max  +0x10 int cur  +0x14 int recommend
  +0x18  char  ip[16]
  +0x28  wchar 显示名[0x40]（宽串，应答里 AddWideStr 的来源）
  +0x268 line_t[16] 线路槽，stride 0x28:
      +0x00  byte  valid（0 = 槽无效）
      +0x04  int   type 闩锁（1=entry，扫描清零）
      +0x08  int   line_id
      +0x0c  int   max
      +0x10  int   cur
      +0x14  int   port
      +0x18  char  ip[16]

生命周期：CheckServer/TimerCheck 周期校验（精确 1s 拍/5s 扫），
超时未刷新的槽清零——注册是持续心跳式，不是一次性登记。
```

### Go 落码要点（已落码：internal/fslister）

- **已实现**：fslister.RegistrationServer（0.0.0.0:Port 绑定，
  reactor.CreateBroadcast 同款语义）+ GameLister.HandlePacket
  （报文门+分发）+ RecvWorldInfo/RecvEntryInfo + Sweep 双心跳扫描
- **Linux 侧零改动**：reactor 纯 stdlib net（已审计无平台分支，
  GOOS=linux 交叉编译过）；netpoller 在 Linux 自动切 epoll
  （对应 Windows IOCP，透明）。广播差异两点：① Linux `lo` 无
  BROADCAST 标志，127.255.255.255 自收是 Windows 环回特性，Linux
  部署用**网段广播**（如 192.168.x.255，需网卡在该网段）或同机
  **定向 127.0.0.1**（官方双口设计本就为此）；② 防火墙放行
  UDP 15000。单测用定向回环，双平台稳定。Linux 下 CGO 常在，
  可跑 `go test -race`（Windows 需 CGO 未开，已知限制）
- lister 独立进程（cmd/lister 已具备载体），`[Broadcast]` 配置键
  解析已在 listerconfig.go 就绪（BroadcastAddr/BroadcastPort 已进结构体）
- 注册表 = `map[serverID]*Server` + 每服 16 槽；心跳 TTL 建议沿用
  CheckClient 同款秒级
- identity 简化：环回口只收 127.0.0.1 来源即可达到同等效果

## 三、busy 动态聚合（应答侧公式，已实现）

`internal/fslister`（FsLister.dll 反汇编细化）与 `internal/fssololister`
（FsSoloLister.dll 反汇编细化）均已按各自官方语义实现：

```
每服扫 16 槽，取 cur/max 负载率最小的一槽作为应答线路
  （大写系：bestrate 1.0f、≤ 比较、等值取后者；
   solo 系：bestrate 10.0f、严格 <、等值取先者）
busy = 服级 cur*5/max；solo 系 world 包带 recommend，>10 直通
IDC>0 时仅 line_id==IDC 的线参与（字段实证=IDC，非 ListerId；两系同）
```

静态来源（-busy 旗标/配置）仍在静态形态（login.Lister）生效。
