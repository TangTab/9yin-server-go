# 击飞击退击倒机制规格书（v1.1，2026-11-18 一期已实现）

> 本文是受控位移/倒地机制（击飞 launch / 击退 push / 击倒 knockdown / 拉近 pull，
> 兼及浮空昏迷 coma 族）的**唯一权威规格**。实现落点 `cmd/protocol-probe/`
> （`control_lease.go` 帧族+租约+解析链；命中链接入 `writeSkillSettleFrames`）
> 与 `internal/`（skillscript/neigong 白名单扩展），代码注释只引本文章节号。
> 证据基线：**群战.pcapng**（官服公会战全量抓包，观测端 0xe0c16d0 视角，
> 17,661 事件）＋ bin2 `fxgamelogic_rebuilt.dll` 字符串 ＋
> `scripts/module/skill/desc_effects.lua`（2,208 条目控制规则数据面）。
> 一期范围：NPC 受害者全帧族+租约+Lua 双侧挂钩；玩家侧闸门先行（无施加源）。
> 标注「待钉死」的字段留真机回归翻案。
>
> **勘误（2026-11-25）**：本文基于 17,661 事件的旧解码。按官服 2433 属性表全量重解（22,752 事件）
> 后，§二「State(183) 整型态状态机」与 §4.4「N=方位角假说」不成立，铁律 2「旁观者零位移流」
> 也不成立；帧族布局（c56 / c78 / c79 / m18）仍有效。详见
> [群战包解码定版与受控机制勘误](../official/群战包解码定版与受控机制勘误.md)。

## 一、概念定界（最高优先级）

**受控 ≠ 霸体，受控位移 ≠ 服务端驱动位移：**

| 概念 | 定义 | 服务端职责 | 客户端职责 |
|---|---|---|---|
| 击飞 launch | 受害者被打上抛物线（hurt_f 族动画） | 广播受控帧簇 + State(183) 整型推送 + 租约 | **自驱位移弧线**（方向=远离 attacker，c79 帧携带 attacker obj） |
| 击退 push | 受害者沿攻击线后滑（hurtbacking/hurtout 族） | 广播受控帧簇（c78） | 自驱后滑位移 |
| 击倒 knockdown | 受害者原地摔倒（hurtdown 族） | State(183)=6+12 同毫秒对 + 租约 | 播倒地/起身动画 |
| 拉近 pull | 受害者被拖向攻击者 | c1=4 申报（语义待钉死，§4.7 二期） | 自驱前移 |

三条铁律（对齐冲锋 §一「客户端自走」哲学，群战.pcapng 定版）：

1. **服务端零 0x21 驱动帧**：全部 138 例 State=6 受控窗口内，受害者 0x21 条目
   只有行走族 intent（0xf01/0xN0000f01），无任何受控 mover 态；击退位移由
   受害者客户端按动画自驱，事后 m15 上报，服务端走既有 absorbClientPosition 收编。
2. **观察者纯动画渲染**：旁观者只收受控帧簇（c78/c79/m18）+ State 推送，
   与「AOI 裸 c61」同哲学——远端零位移流。
3. **控制是租约不是标志位**：服务端记 `controlLease{kind, until, attacker}`
   （封招/封轻功/起身定时的权威依据），客户端记动画。两端各自到期，
   服务端租约到期即推 State=1（起身），不依赖客户端申报。

## 二、状态机（State 属性 idx183 的整型态）

State(183) 双形态：**字符串态**（"stand"/"walk" 等，patrol.go 已用）与
**整型态**（受控状态机，群战.pcapng 401 例推送实证）。整型按 float32 位型
存放（观测值 1.4e-45=1、8.4e-45=6、1.68e-44=12、1.82e-44=13）。

| State | 语义 | 证据 |
|---|---|---|
| 1 | 常态（战斗站立） | 12/13 起身后回归，全部 6→12 链终点 |
| 4 / 5 | 落地双态（自愿跳） | obj 0xe011986 全程 6→5、0xe004342 全程 6→4 |
| 6 | 腾空（自愿跳起 & 受控抛起共用） | 138 例；受控形=与 12 **同毫秒成对** |
| 7 / 8 | 移动 / 下落（m15 自报域） | 既有方言，非本规格对象 |
| **12** | **倒地**（击倒落态；击飞下落终点） | 61 例；与 6 成对或继 13 后 0.2s |
| **13** | **浮空受击/昏迷瘫倒** | 11 例；与 c79 hurt_f 同毫秒（5.500 样本），或昏迷技直推 |

**生命周期三形**（群战.pcapng 逐例）：

```
击倒（无滞空）  State=6 →(同ms)→ State=12 →(0.55~3.0s, 随 control_dur_ms)→ State=1
击飞（抛物线）  c79[hurt_f_1_l] → State=13 →(空中段, 再受击=c79 裸帧维持)→ State=12 → State=1
昏迷（ coma ）  State=13 →(control_dur_ms)→ State=12（或直 1）→ State=1
击退（不换态）  c78 → State 不变（429~432s hurtouting 四连窗口零 State 推送）
```

12→1 间隔观测：0.55/0.6/0.65/1.0/1.03/1.5/2.1/3.0s——离散分布=按技能
control_dur_ms 而非定长。**起身由服务端租约定时器推 State=1**（观测端无
任何 m15/m212 先行申报）。

## 四、帧型细则

### 4.1 击飞簇（launch）

```
m19(伤害, 已有) → m18[victim, "hurt_f_1_s" 若首发, 0, attacker] → c56 → c56 →
c79[victim, 79, attacker, "hurt_f_1_l"] → State(183)=13 →
[空中再受击：c79 裸帧（无动画名），维持 13，不重置租约] →
下落自动 → State=12（服务端定时：air_ms 后推）→ 租约到 → State=1
```

- 首发动画名从 desc 无关，客户端按武器位自解析（`hurt_f_1_l` 为观测实发值，
  直发即可；`_l/_s` 为长/短变体，服务端只发 `_l`）。
- 方向：客户端取 attacker obj 位姿反推抛掷向（帧内无显式向量——与 c61
  「dest 即指令」不同，受控帧只发关系，几何全在客户端）。
- **空中追击（juggle）**：受害者 State=13 期间被再次命中=只发 `c79[victim,
  79, attacker, ""]` 裸帧（观测 5.279~6.776 六连发均裸），租约不刷新
  （观测 12 出现在最后一击后 0.2s——下落由客户端动画时长自定，服务端
  air_ms 定时器与动画时长解耦，先到者推 12）。

### 4.2 击倒簇（knockdown）

```
m19 → m18["hurt_half"] → c56 → State(183)=6 → State(183)=12（同毫秒两推送）→
租约(control_dur_ms)到 → State(183)=1
```

- 官方零动画帧（138 例全纯 State 对）——倒地/起身动画由客户端状态机
  按 hurtdown 族字典自选。
- NPC 受害者同帧族（客户端按 obj 泛化处理）；服务端侧另冻结 AI 索敌
  （§七）。

### 4.3 击退簇（push）

```
m19 → m18["hurt_half"] → c56 → c56 →
c78[victim, 78, attacker, "", "", N, 100000000.0] →（State 不变）
```

- 位移=客户端 hurtbacking 滑行动画自驱；服务端位置收编等受害者 m15。
- 变体 `hurtouting` 形（大位移出场，0.564）：竞技场/悬崖出场击退用，
  一期直发标准形。

### 4.4 c78 的 N 值（待钉死）

观测 N∈{5, 6, 14, 68, 109, 119, 167}，全部落在 0..180——**方位角假说**
（攻击线偏角，度）。实现先按 `atan2` 攻击线方位发（0=正北顺时针），真机
回归核对观感；翻案权留抓包。1e+08 恒值原样复刻（疑似「无衰减速度」标记，
与 wujiComboFloatFrame 的 30.0 同款「含义未钉死常量」处理）。

### 4.5 招架/条件门（触发前置）

desc_effects 的 DescRule 自带条件（`unparried` 未招架 / `parry_broken` 已被
破防 / `target_state`）与 `chance`。判定序（官方观测 txd08 招架期 c1=4 连发
但零 State=12——条件门在服务端）：

```
招架中(InParry) 且规则要求 unparried → 免控（只走既有 hurt_half 链）
霸体帧（红/黄，CantPlayHurtAction 位）→ 免控
轻功 state7/6 空中 → 击倒改判击飞（c79 追击规则 §4.1）
chance 掷 → 调用方预掷（对齐 on_hit rand.r_adjust 契约，无钩子技能 RNG 零扰动）
```

### 4.6 连锁击退（链式）

复用 c71 wujiComboFloatFrame：链主命中首目标后逐段 `[前受害者, 71, 下一
受害者, "", 1, 链主, 30.0, 0.0, "cs_0h_N"]`（N=段号，武器位 0h 全空手链），
段间隔 0.4~0.5s（观测 312.7~316.2 八段）。链上每目标同发 c79 击飞簇
（观测 315.366 三目标同毫秒 State=13）。

### 4.7 拉近 pull（二期，本期只留桩）

观测全部来自 CS_jh_txd08（desc=knockdown/unparried，但抓包呈 `[victim, 4,
attacker, 1, 2000, dist]` 逐击连发且受害者纹丝不动）——语义两解：击退位移
申报（dist=当前距离）或拉近拖拽。**一期不发**，desc 拉近技（34 条）先落
击退形（push 反向=服务端无法表达，观感以 c78 attacker 关系帧为准，客户端
按动画方向自决）；真机钉死后开二期。

## 六、服务端权威模型（controlLease）

新文件 `cmd/protocol-probe/control_lease.go`：`playerActor`/`npcActor` 挂
`controlLease{kind string; until time.Time; attackerID uint32; airTimer
*time.Timer}`。

- **封招**：m211 受理（stageRushCast/直收入口）遇活跃租约且 kind∈
  {launch, knockdown, coma, stun} → 静默拒（官方受控零受理回包，观测
  12/13 期间受害者零 m211）。
- **封轻功**：跳/穿云纵上报（m15 state5/6 起跳族）遇租约 → 不授 JumpTimes
  （镜像协议 §九 JumpTimes 授权位即天然闸门；mirrorJumpTimes 锁内闸）。
- **位置收编窗口**（二期）：absorbClientPosition 当前无瞬移校验可门控，
  窗口闸随瞬移校验一并落地。
- **起身定时**：租约到期回调推 `State=1`（经受害者 link 私有 + AOI 中继，
  与受控帧同路由）；租约被新受控覆盖时按 recoverAt 对账戳让旧定时器退场。
- **重复受控**：12/13 态再被击 → 刷新租约 + 重推对应帧簇（12 态被击飞技
  命中 → 直接 13，不走 6）。
- **死亡优先**：HP≤0 击杀链（0x0E/死亡帧）先于受控簇结算，击杀补刀走
  既有 c29。

## 十、真机判据（日志锚）

## 十一、待钉死清单（真机回归翻案项）

1. c78 N 值语义（§4.4 方位角假说）与 1e8 尾值。
2. c1=4 拉近/击退申报两解（§4.7，txd08 专项抓包）。
3. State 12 与 13 的昏迷归属边界（yydf03=coma 直推 13；「击飞落地后躺」
   是否短暂 13 还是直 12）。
4. NPC 受控方言（客户端泛化假设的验证；NPC LogicState 冻结时长）。
5. 击退是否刷新既有 12/13 租约（观测样本零交叉，暂按「不同族互不刷新、
