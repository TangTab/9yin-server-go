# 客户端逆向数据附录：玩家状态机注册表与 m24 子码处理表

> 数据源：外服客户端内存 dump `fxgame.DMP`（FxGameLogic.dll 基址 0x39e0000、FxProtect.dll 基址
> 0x8d00000）与本地客户端 `bin64/fxgamelogic.dll`（ImageBase 0x11000000），2026-11-26 用
> `tools/clientbin` 导出。两版客户端的 m24 处理表逐子码对拍：有处理函数的子码里，除 6 个外
> 引用的字符串完全相同。解读与用法见《[寒心恨雪与太极剑舞引导机制](寒心恨雪与太极剑舞引导机制.md)》
> §十；本篇只放数据与再生成方法，数值以工具输出为准，不手改。

## 一、再生成

```bash
# 0) 看各模块基址
python -I tools/clientbin/mdmp.py fxgame.DMP info

# 1) 模块镜像按基址整段落盘（落盘后 VA = 基址 + 文件偏移）
python -I tools/clientbin/mdmp.py fxgame.DMP save FxGameLogic out/fxgamelogic_mem.bin

# 2) m24 子码 → 处理函数（外服镜像 / 本地 DLL）
python -I tools/clientbin/subtab.py mem out/fxgamelogic_mem.bin 39e0000 out/m24_foreign.txt
python -I tools/clientbin/subtab.py pe  <客户端>/bin64/fxgamelogic.dll out/m24_local.txt

# 3) 玩家状态机状态注册表（直接读 dump）
python -I tools/clientbin/stateconst.py fxgame.DMP out/statetable.txt
```

依赖只有 `capstone`（`pip install capstone`）。dump、DLL、抓包都是外来数据：脚本放仓库里，
数据路径当参数传，Python 用 `-I` 跑。

## 二、玩家状态机状态注册表（外服 FxProtect.dll）

状态机逻辑被 VMProtect 虚拟化，读不出迁移代码；但运行期它把「索引 → 状态名」注册在
FxProtect.dll 的堆上，按索引连续排列，每项 0x28 字节：

```
{ u64 索引; char* 状态名; void* 入口; u32 标志A; u32 标志B; u64 扩展 }
```

表在模块内 `+0x1ee5c8 .. +0x1efbd0`，共 141 项、索引 1..141 连续无缺。`入口` 是 FxProtect.dll
代码段里的地址（虚拟机桩，反汇编无意义）。`标志A / 标志B / 扩展` 是原样数值：标志A 只见过
0 / 1 / 256 / 257，标志B 只见过 0~8，扩展只有 0 和 1，含义未定。与闪击直接相关的两行是
**123 `player_flash_attack`** 与 **124 `player_flash_stop`**——fxgamelogic 的 m24 子码 71 处理
函数切的就是 123 号状态（见 §五）。

## 三、m24 子码 → 处理函数（两版客户端对拍）

m24（自定义消息 24）在 fxgamelogic 里先取第 2 个值的对象名与第 3 个值的子码，再把**第 4 个值
起**的子表交给处理函数：

```
lea  eax, [rcx - 1]          ; rcx = 子码
cmp  eax, <上限>             ; 本地 0x61 / 外服 0x5e（版本相关）
ja   done                    ; 合法子码 = 1 .. 上限+1
lea  r9, [表基址]            ; 本地 0x13269200 / 外服 0x58101d0
movsxd rax, ecx
mov  r9, [r9 + rax*8]        ; 槽 = 表基址 + 8 × 子码
…    jmp r9                  ; 处理函数(对象名, 子表)
```

处理函数里引用的字符串是判断子码语义最快的线索。下表 `字符串` 一列按函数体内出现顺序列出
（单个串截到 52 字符）；「对拍」是两版字符串集合的比较结果。

- 本地客户端合法子码 1..98，其中 12 个没有处理函数：50、82、86~92、95、96、97。
- 外服客户端合法子码 1..95，其中 10 个没有处理函数：50、82、86~92、95。
- 两版都有处理函数但函数体内没有任何字符串引用的子码：4、5、6、9、34、38、40、53、93。

## 四、过场窗体打开期间的子码过滤

分发之前有一处特判（顶层函数 `0x12a21f30`）：过场窗体 `form_stage_main\form_movie_new` 打开
期间，**只处理子码 69（buffer_action）、70（倒地循环）、41 三个**，其余子码连同子表一起丢弃、
函数返回假。寒心恨雪的大招演出是否用这个窗体没有核对，所以它的 c71 等帧是否受此过滤影响未知。

## 五、子码 71（闪击）处理函数的取值下标

处理函数拿到的是 m24 去掉前三个值（消息号、对象、子码）后的子表，下标固定（本地
`0x12a071f0` 与外服 `0x50964e0` 两版反汇编逐指令一致，1266 字节）：

| 子表下标 | m24 数组下标 | 类型 | 客户端用途 |
|---:|---:|---|---|
| 0 | 3 | 对象 | 处理函数把它转成「低 32 位-高 32 位」的键字符串去查一个对象，查到的位置写进施法者的 `flash_end` |
| 1 | 4 | 字符串 | 原样传给位移启动调用的名称参数（官服恒为空串） |
| 2 | 5 | 整数 | **必须等于 1**，否则处理函数直接返回 |
| 3 | 6 | 对象 | 施法者：下面各项都设到它身上 |
| 4 | 7 | 浮点 | `tm_speed`（官服 30.0，m/s） |
| 5 | 8 | 浮点 | `tm_add`（官服 0.0） |
| 6 | 9 | 字符串 | `tm_action`：施法者的位移动作名 |
| 7 | 10 | 浮点 | `tm_back_dist`；**子表长度 > 8 才读**，否则 0 |
| 8 | 11 | 字符串 | `tm_behit_action`；**子表长度 > 8 才读**，否则空串 |
| 9 | 12 | 浮点 | `tm_stop_time`；**子表长度 > 9 才读**，否则 1.0 秒 |

两个对象的线位是按落点关系对上的，不是从指令上读全的（查对象那一步的键构造没看懂）：

- **数组下标 3 是终点**。官服每一波在这一位放本波目标，m914 落点与它的实位偏差中位
  0.0001 米（34 跳）。
- **数组下标 1 是起点**。处理函数的首参不是子表里的值，而是 m24 第 2 个值那个对象转成的
  字符串（顶层函数 `0x12a21f30` 先取对象、转字符串，再连同子表交给处理函数）。官服后续波在
  这一位放上一跳的目标——施法者此刻正站在它的位置上，逐跳时延也正是按「上一跳落点 → 本跳
  目标」的距离线性拟合的；首波放目标自身。

设完属性后：若施法者当前已是 123 号状态，只把 `need_re_init_flash_attack` 置真（不重复切状态）；
否则调用状态机的 `vt+0x58`（切状态）切到 `player_flash_attack` / 123。两版客户端在这段上逐指令
一致。
