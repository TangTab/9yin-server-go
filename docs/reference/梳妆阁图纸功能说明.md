# 梳妆阁图纸 + 身份装外观显示 实现说明

只改服务端（cmd/protocol-probe），客户端与 DLL 均未动。全部外观数据链路均来自官方协议逆向确认。

## 一、客户端协议结论（逆向依据）

1. **图纸是否可用**：由玩家记录 `blend_collect_rec` 决定（原生 AttireItemActive / GetAttireItemConfigList 的数据源）：
   - col0=图纸ConfigID（string，如 `Tab_b_cloth_001`）
   - col1=OWNNUM 拥有数量（int）
   - col2=USEDNUM 已使用数量（int）
   - col3=ACTIVE 激活标志（int）
2. **点击"保存"**：客户端发 `CustomSend(692, use_type, info)`（CLIENT_CUSTOMMSG_ATTIRE_EQUIP_BLEND=692，lua 的 custom_attire_equip_blend）。
   - info = `"图纸ConfigID,装备uid,图纸ConfigID,uid,..."`；套装路径额外带 `";index;flag"` 段。
   - use_type：0=银子 1=火浣布 2=免面板直存 3=套装索引（私服全部免费直存）。
3. **图纸条目**：tool_item.ini 节名 `Tab_b_*`（男）/`Tab_g_*`（女），ItemType 601/602/603/604 = 帽/衣/裤/鞋图纸；模型 = ArtPack → itemartstatic.ini 的 MaleModel/FemaleModel。
4. **外观模型**：客户端原生合成器直接读场景对象属性 `Mask/Hat/Cloth/Pants/Shoes/Mantle/Cloak/Waist`（DLL 0x12CE7200 属性表）；`ShowEquipType==1`（身份装）时原生层会再叠加一次 Cloth。
5. **面板切换**：人物属性面板已有 江湖装/身份装/时装 单选钮，发 `CustomSend(61, type)`（CLIENT_CUSTOMMSG_SHOWEQUIP_TYPE=61）。

## 二、服务端实现（新增 attire_blend.go + 接线）

### 数据流

| 环节 | 实现 |
|---|---|
| 图纸目录 | 启动时解析 `resources/modern/share/item/tool_item.ini`（Tab_*，ItemType 601-604），模型经已加载的 itemartstatic 表解析 → 共 2393 张图纸 |
| 全解锁 | 登录/切场景重入时推送 `blend_collect_rec`（record index 25，先清后推），每张图纸 OWN=1/USED=0/**ACTIVE=1** → 梳妆阁面板全部可用 |
| 保存覆盖 | C2S **692** 分发到 `handleAttireEquipBlendCustom`：解析图纸对→按性别过滤→存入槽位映射→`data/梳妆阁数据.json` 持久化→立即重推外观帧（无需重登） |
| 身份装显示 | `pushGearVisual`：ShowEquipType==1 时用保存的图纸模型覆盖 Hat/Cloth/Pants/Shoes（未保存的槽位回落真实装备） |
| 三档优先级 | 江湖装(0)=真实装备；身份装(1)=梳妆阁融合外观；时装(2)=风物志卡牌（原有逻辑不变） |
| 切换持久化 | 61 号消息处理扩展：选择写入 `data/梳妆阁数据.json`，并整体重推 `pushGearVisual`，切档即时换模型 |

### 存档格式 data/梳妆阁数据.json

```json
{
  "version": 1,
  "roles": {
    "12345": {
      "blend": { "Hat": "Tab_b_helmet_001", "Cloth": "Tab_b_cloth_001", "Pants": "Tab_b_pants_001", "Shoes": "Tab_b_shoes_001" },
      "show_type": 1
    }
  }
}
```

每个角色独立存档，登录自动恢复融合外观与上次的显示档位。

## 三、使用方式

1. 进游戏打开梳妆阁（C 面板 → 梳妆阁入口）→ 图纸列表全部"已激活"。
2. 选中图纸 → 点"保存"（不再扣银子/火浣布）→ 模型立刻覆盖到装备外观上。
3. 打开人物属性面板（C）→ 装备页右上 江湖装 / 身份装 / 时装 单选：
   - **江湖装**：显示真实装备外观
   - **身份装**：显示梳妆阁保存的图纸融合外观（即"保存覆盖到装备模型身上"的效果）
   - **时装**：显示风物志卡牌外观（原有功能）
4. 选择与融合外观跨登录、跨切场景保留。

## 补充：保存后即时替换装备模型（2026-09-04 晚2）
692 保存的"图纸,装备uid"对官方语义是**把图纸绑定到具体装备件、替换该件外观**，
不是身份装档位的专属覆盖。pushGearVisual 已改为所有档位（江湖装/身份装）生效，
保存后立即换装；优先级=风物志卡牌（时装档，逐槽）> 图纸融合 > 真实装备。
「恢复默认」按钮为纯客户端行为（清预览），不发服务端消息。

## 补充：装备图标替换为图纸图标（2026-09-04 晚3）
官方语义：图纸绑定到装备件后，该装备的**图标**也要换成图纸图标。机制在客户端
`util_static_data.lua query_equip_photo_by_sex`：装备对象带
`ReplacePack`（数字美术 id，>0）+ `ReplaceID`（图纸 ConfigID）时，图标改查
`itemartstatic[ReplacePack]` 的 Photo/FemalePhoto（ReplaceID 的 LogicPack.
UseSex 决定男女图）。注意：直发 `Photo` 属性优先级最高，会遮住 ReplacePack，
因此融合槽位的装备必须撤掉直发 Photo。

服务端实现：
- 0x09 协商表追加 ReplacePack=338(WireInt32) / ReplaceID=339(WireString)；
- `playerLoot.attireBlendSlots`（装备槽号→图纸条目）在 692 保存与登录还原时
  由 `syncAttireBlendSlotsLocked` 重建；
- `equipViewProps`：融合槽位撤 Photo、补 ReplacePack/ReplaceID；普通槽位不变；
- 692 保存后对帽/衣/裤/鞋有装备的槽位 remove-then-add 重推 view 1 行，
  图标即时替换（无需重登）。

回归：TestEquipViewPropsUseBlendReplaceID、协商表连续性测试。

## 补充：绑定改物品级——只改那一件装备（2026-09-04 晚4）
官方语义：图纸绑定的是**具体那件装备**（692 的"图纸,装备uid"对；tooltip 有
"此物已参照『图纸』进行了改造，外 prevail 风样式发生了改变"）。此前实现按
槽位固定（换穿别的装备仍显示旧图纸模型、卸下图纸装备后身上没模型）。

修正：
- 绑定 key 从槽位名改为物品 uid（itemUniqueID，即下发的 UniqueID，
  客户端 692 原样回传）；
- 模型：pushGearVisual 逐槽查当前穿着物品的 uid——穿着被绑定的装备才替换
  模型；卸下→该槽显示新装备自己的模型，再穿回→图纸模型回来；
- 图标：全局 uid 索引（attireBlendUIDIndex）由 itemViewProps 统一查，
  装备/背包/掉落所有视图自动携带 ReplacePack/ReplaceID，图标跟着物品走
  （卸到背包也是图纸图标，tooltip 改造提示同样保留）。
- 优先级不变：风物志卡牌（逐槽）> 图纸融合 > 真实装备。
- 旧存档（槽位名 key）自然失效，无有害影响，重新保存一次即可。
