# 大轻功激活记录两列模型修复说明

> 2026-09-14 第六轮。核心诉求：「御风是没问题的，我的意思是大轻功用不出来」——御风 buff 正常挂载，但二段跳始终进不了大轻功（客户端只发 216 qinggong_9，从不发 728 qinggong_20/21，且无任何提示）。

## 一、根因（fxgamelogic.dll 反编译闭环）

客户端二段跳进大轻功要过引擎门槛（GATE），而门槛的**第一道隐形检查**是查询 `ActiveQGSkillRec` 记录表：

1. **MOD_GETSTR**（0x12856950，qinggong 模块 vtable+0x60，无参）**硬编码按 `[col=1, 值=21]` 查询 ActiveQGSkillRec**：
   - 构造查询变体 `vt+0x40(1)`、`vt+0x40(0x15=21)` → `client vt+0x110(name, params, &out)` → out 按变体类型取 int；
   - **int < 0（查不到）→ 返回字符串 "0"**；≥ 0 → `vt+0xF8` 取动作名返回。
2. **GATE_ACT20（0x1284EB60，type 20 门槛）与 GATE_DBLJUMP（0x1284EED0，二段跳门槛）的第一道检查都是 `MOD_GETSTR != "0"`**，失败**纯静默**——没有任何提示、不发 728、退回普通二段跳 216 qinggong_9。
3. 服务端旧模型是**单列**（只写 col0=技能名）→ 客户端按 col1=21 查询时越界失败 → 返回 "0" → 门槛静默 false。**御风、轻功点数、习得表全都没问题**——之前几轮修的都是外围。

## 二、决定性证据（官服抓包）

`capture-players/out2/timeline.txt:29840` 官服登录初始下发：

```
[S2C] record add rec=117(ActiveQGSkillRec) rows=6
  QG_JH_05_001,5 | QG_JH_04_001,4 | QG_JH_03_001,3 | QG_JH_06_001,6
  | QG_JH_gjskill_001,20 | QG_JH_gj_003,21
```

**两列模型**：col0=技能名(string)、col1=轻功系统类型 ID(int)，多行激活集合。`gjskill_001(秘策·云行九霄)→20`、`gj_003(捉云履月)→21`。此前 09-12 抓包只见到尾端覆写帧、没抓到登录建行帧，所以误建了单列模型。

附带实锤：`ActiveQGSkillRec` 在 fxgamelogic.dll 内**只读不写**（仅 MOD_GETSTR 与 UI tooltip 115514C0 两处引用）——值只能由服务端记录表下发，C2S 217 激活仍由服务端处理（已在）。

## 三、修复内容

### 1. `cmd/protocol-probe/qinggong_records.go`（核心）

- schema 两列化：`colTypes: []byte{recordColumnString, recordColumnInt}`（官服实证注释）。
- 新增映射：

```go
func activeQingGongTypeValue(id string) uint32 {
    if id == "QG_JH_gjskill_001" { return 20 }
    return 21
}
```

- `writeActiveQingGongSlot`：占位行改两 cell 空行（`recordString("")+recordInt(0)`，补 [12:14] 行号）；覆写 grid 改双 update（row2col0=技能名 + row2col1=类型 ID）。
- `activateQingGongRecord`：激活时同步写 col1。
- `deactivateQingGongRecord`：关闭时 col1 与 col0 同步清空（remaining 空 → col1=0）。

### 2. `cmd/protocol-probe/qinggong_official_props.go`

0x09 属性表补 698..703 官服段（对齐官服 propstable.txt）：

| 下标 | 属性 | 类型 |
|---|---|---|
| 698 | CantUseQingGong | byte |
| 699 | CantUseQingGongQJ | byte |
| **700** | **AdvancedQGFlyRushs** | **int32** |
| 701 | OnTransToolState | byte |
| 702 | LinkObj | object |
| 703 | InSuperTransMode | byte |

原因：GATE_DBLJUMP 御风蓄力分支（`[0x5C0]==0x8A`）会 `vt+0x70` **按名查 "AdvancedQGFlyRushs"**（vt+0x70 = 按名读 0x09 属性表）。名字未登记 → 查询返回负值 → js → 门槛 false。值本身仍是客户端本地计数器（默认 0，官服零下发），但**名字必须在表内**。

### 3. `cmd/protocol-probe/qinggong_records_test.go`

`TestActivateQingGongWritesActiveSkillRecord` 末尾加回归断言：切换激活帧必须含 `col1=21`（`bytes.Contains(grid, []byte{0x15, 0, 0, 0})`）。
