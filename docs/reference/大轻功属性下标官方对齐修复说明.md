# 大轻功资源属性下标官方对齐修复说明

**日期**: 2026-09-14
**问题**: 客户端二段跳始终回落初级轻功（只发 `216 qinggong_9`，从不发 `728 qinggong_20`），无法进入大轻功状态。

---

## 一、本轮逆向结论（fxgamelogic.dll 大轻功门判定全链）

用字符串交叉引用 + capstone 反汇编完整解码了二段跳→大轻功的客户端全部门槛：

| 函数 | 作用 | 关键条件 |
|---|---|---|
| `0x1284EED0` | 二段跳发射许可 | `[实体+0x38]` 动作对象 +0x5C0 ∈ {0x88,0x8A}（御风蓄力创建的 useitem_flow 对象） |
| `0x128512A0` | 大轻功总门槛 | buffer_action 空 → 不在马上 → 区域标记 `qinggong_limit` → **is_learned（QingGongRec 按名，值≥0）** → CantUseQingGong≤0 → **GJQingGongPoint ≥ QGDefine Consume**（vtable+0x70 按名读） |
| `0x1284EB60` | 动作 20 专属终检 | `[actor+0x38]` 类 ID ∈ {3,12,13} + **HasBuff("buf_ride_yufeng") 必须 true** + LogicState≠1 |
| `0x1284F2D0` | 动作 24（滑翔）终检 | HasBuff("buf_ride_yufeng")=true 且 HasBuff("buf_qg_gliding")=false |
| `0x12854D30` | 开始动作入口 | **引擎自己写** `qinggong_type`/`qinggong_id` 实体属性 |

## 二、根因分析（三层）

### 1. 官方硬前置：御风 buff（行为规则，非服务端缺陷）
官服抓包报告的操作流程第一句就是「**使用御风道具 → 起跳 → 二段跳进入大轻功**」。
`0x1284EB60` 反汇编实证 `HasBuff("buf_ride_yufeng")` 是动作 20/24 的硬条件。
**没有御风 buff 时二段跳必然回落 qinggong_9——这是官方规则。**

### 2. 资源属性下标与官方注册表错位（本轮修复）
官服 0x09 属性表 dump（`artifacts/capture-players/out2/propstable.txt`，0..2425 全量表）实证官方下标：

| 官方下标 | 官方属性名 | 我们原下标 | 官方原下标语义（被我们污染） |
|---|---|---|---|
| 692 | QingGongPoint | 114 | CommonSigninGet（签到） |
| 693 | MaxQingGongPoint | 115 | DoubleXiuLianSelfPoint |
| 694 | MaxQingGongPointAdd | 116 | DoubleXiuLianMemberPoint |
| **695** | **GJQingGongPoint** | **358** | TeamUniqueID（string！） |
| 696 | MaxGJQingGongPoint | 359 | CurEquipScheme |
| 697 | MaxGJQingGongPointAdd | 360 | TitleID |
| 361 | CurRideMount(object) | （我们发 AdvancedQGFlyRushs int） |
| 362 | MountJumpSpeed(float) | （我们发 CurQingGongType int） |

官服实时 vital 走 `0x2b7(695)`，`0x180(384)=MoveSpeed` 与注册表吻合——**0x10 vital 通道 index 就是引擎内部注册表索引**。

### 3. AdvancedQGFlyRushs / CurQingGongType 撤除（官服零下发实证）
官服抓包发现 2：官服**全程零下发**这两个属性——它们是客户端本地维护的计数器
（`0x12854D30` 开始动作时引擎自写 `qinggong_type/qinggong_id`，每次冲刺自增段位）。
第五轮「由服务端同步」的结论被官服实测推翻；且 361/362 官方语义是
CurRideMount/MountJumpSpeed，下发 int 值属于污染。

## 三、修复内容

1. **`qinggong_records.go`**：六件套常量改为官方下标 692..697；删除 `propAdvancedQGFlyRushs/propCurQingGongType`。
2. **`qinggong_official_props.go`（新文件）**：官方下标补齐段——114..116、358..362 按官方语义占位 + 376..691 官方真实属性名（由 `artifacts/gen_official_prop_gap.py` 从 propstable.txt 生成）。只声明不下发值。
3. **`main.go`**：
   - 0x09 表：删除中段 114..116 旧声明与 358..362 GJ/链两件套声明；表尾 PVP 块后按升序登记六件套；`officialQingGongGapFields()` 挂到 `orderedScenePropertyFields` 前（表 index 严格连续，0x09 线上帧不带 index、表项位置即属性号）。
   - 728 链三处 `qingGongStateUpdate()` 调用删除（链路状态仅服务端逻辑用）。
   - 216 接受/拒绝日志增加 `yufengBuffSlot=N`（0=无御风 buff），实测时可直接分辨官方前置是否满足。
4. **`player_actor.go`**：`stateProperties`/`vitalUpdate` 六件套改官方下标；vitalUpdate 补发 GJ 三件套（官服链路节点以 vital 0x2b7 推送，扣点后客户端条数同步）；删除 `qingGongStateUpdate()`。

## 四、实测步骤（重要）

**2026-09-14 20:5x 更新：已实现「3 秒内连续跳跃直接进入大轻功」，不再需要手动加御风。**

### 自动御风（新）
- 服务端在玩家发起轻功跳（`216 qinggong_9` 等非链动作开始帧）且尚无御风 buff 时，**静默自动补挂御风状态**（官服两阶段帧序一次推完：蓄力开始→立即完成，不等 249/20s 兜底，玩家无感）。
- 时序效果：第一跳毫秒级挂上 `buf_ride_yufeng` → 紧接着的二段跳原生通过客户端全部门槛 → 发 `728 qinggong_20` → **进大轻功**。即「3 秒内连续跳跃（跳+二段跳）直接进入大轻功」。
- 御风持续 10 分钟，期间任何二段跳都直接进大轻功；过期后下一次跳跃自动续挂（无需任何手动操作）。
- 实现位置：`yufeng_wind.go autoGrantYufengForJumpChain` + `main.go handleQingGongCustom` 非链动作开始路径调用。
- 日志判据：`auto yufeng granted for jump-chain qinggong entry` → 随后 `accepted qinggong id=qinggong_20`（或 728 到达）即全链通。

### 手动步骤（仍可用，作为对照）
1. 启动新编译的服务端。
2. （可选对照）GM 面板 →「御风神水」→「添加御风状态」，或使用御风神水道具。
3. 起跳 → 二段跳 → 客户端应发 `728 qinggong_20`（日志 `accepted qinggong id=qinggong_20 ... yufengBuffSlot=11`）。
4. 若日志 `yufengBuffSlot=0`：御风 buff 未挂上（查 0xA9 通道）；若御风在身仍失败：换开阔野外地图再测（区域 `qinggong_limit` 标记嫌疑），并查客户端 qgdefine.ini 的 qinggong_20 Consume 列。
