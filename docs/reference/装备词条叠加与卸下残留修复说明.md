# 装备词条叠加与卸下残留修复说明

日期：2026-09-07
涉及：`cmd/protocol-probe/skill_combat.go`、`cmd/protocol-probe/weapon_recast.go`

## 问题清单

1. **卸下武器后招式威力加成仍然生效**（要求：只有装备着才加成，卸下即清除）。
2. **淬炼洗出 2-3 条相同招式词条，保存后被合并成只显示 1 条**（要求：3 条显示 3 条，加成按条数叠加）。
3. **GM 后台追加词条报「所选词条均已存在，未追加任何词条」**（要求：无条件追加，允许重复）。

## 根因与修复

### ① 卸下武器加成残留 —— 施法加成烙进了技能定义缓存

`installedCombatSkillCatalog.definition()` 按 {id, level} 缓存 `combatSkillDefinition`，
按值返回。标量字段复制没问题，但 **effects 切片的底层数组与缓存共享**。

施法流程（`handleUseSkillCustom` 内）有两处直接原地改 `definition.effects[i].amount`：

- 装备近身属性加成（`loot.equipMaxMelee`）；
- 招式威力词条加成（`equippedSkillDamageBonusFor`）。

结果：第一次带加成施法就把 +N% **永久焊进缓存定义**——卸下武器后加成照旧，
反复穿戴还会每次施法继续叠加（越打越疼）。

修复：新增 `cloneSkillDefinitionForCast()`，施法时先克隆 effects 再做加成折算，
加成只作用于本次施法，缓存永远保持干净。

```go
// skill_combat.go
definition = cloneSkillDefinitionForCast(definition) // 克隆 effects 后再折算加成
```

### ② 保存时重复词条被合并 —— 去重误伤

`applyRecastResult` 的招式词条分支原来写了
`item.SkillPackRecs = dedupeInt32(packs)`，把 2-3 条相同词条压成 1 条。

修复：招式词条原样保存，不做去重。官方语义就是重复词条各自独立一行显示
（record 29 每条 rec 一行），威力按条数叠加（1成=+10%，2条=+20%，3条=+30%），
聚合端 `equippedSkillDamageBonusFrom` 本来就按条数累加，不受影响。

注意：`skillPackSkills` 装载期的集合去重（防 +5175% ×5 事故）**保留**——
那是对「同一个 pack 内同一招式的 5 个伤害乘区行」去重，与词条条数叠加是两回事。

### ③ GM 追加词条被查重拒绝

`runGMRecastAddAffix` 的 prop/skill 两个分支都先查重、全命中就报错拒绝。

修复：两个分支均改为**无条件追加**（`packs = 现有词条 + 所选词条`），
删除「均已存在」的拒绝逻辑。重复 prop 词条由 `SumPacks` 累加，
重复招式词条由 `equippedSkillDamageBonusFrom` 按条数叠加。
