# 淬炼招式按真实兵器限制过滤修复说明

## 2026-09-07 二次修订：护腕只出徒手+暗器

### 问题现象

淬炼（C2S 935 op=5）护腕时，持单剑的角色会洗出**剑法**套路词条：

```
recast preview view=121 slot=8 op=5 config=wrist_60501 candidates=[30221 30222 12602]
```

30221/30222=幻欲剑（UseLimit=2 单剑）、12602=单剑系，全部不该出现在护腕上。

### 根因

旧实现 `recastSkillWeaponType` 对防具/护腕取**身上主手武器**的 ItemType 做过滤
（当时理解为"官方护腕出徒手词条"）。持单剑淬护腕 → 过滤口径变成单剑 → 剑法
词条全放进来；未持武器时 weaponType=0 → 完全不过滤，什么都能洗出。

### 修复方案：护腕固定口径 = 徒手 + 暗器（与身上武器无关）

- `recastSkillScope`：武器本体 → `weaponType` 精确匹配（不变）；护腕/防具 →
  `armor` 口径，候选只允许：
  1. **UseLimit 声明的兵器类型全部落在暗器区间 111-117**（针/弹丸/飞刀/飞镖/
     机括/绳索/毒虫）——即暗器套路；
  2. 无 UseLimit 声明时，用客户端同源 `desc3.idres` 套路描述的**「兵器限制：X」
     字段**兜底：`X=无` → 徒手套路放行；`X` 含暗器关键词（针/弹丸/飞刀/飞镖/
     机括/绳索/毒虫/袖箭）→ 放行；其它（如流沙描述"单剑"、太极剑"单剑"）→
     排除；完全没有依据（新手段落，服务端未实装其技能，受"已学"约束本就不
     会进候选）→ 排除。
- 删除 `recastSkillWeaponType`（防具取身上武器）；GM 护腕模板生成
  （`gmGenerateBracer`）同步改为徒手+暗器口径。
- 武器本体淬炼行为不变（单剑只出单剑限制套路）。

### 真实数据验证（1 成 pack 全量模拟）

- 放行：太极拳/太祖长拳/莲花掌/腐骨掌/龙爪手/逍遥腿法/金顶绵掌…（徒手）＋
  迷魂镖/金蛇刺/阎王帖/织罗针/三阳玄针/玲珑骰/天地搜魂锁/追魂爪/天魔追魂刀
  （声明飞刀 113，暗器套路）…（暗器）；
- 排除：幻欲剑/流沙/太极剑/清风剑法/两仪剑法/达摩棍法/失魂刀法…全部兵器套路。

### 单测

- `TestRollSkillRandWristOnlyFistOrAnqi`（回归）：持单剑淬护腕只出徒手+暗器；
- `TestRecastSkillScopeFor` / `TestRecastPackFistOrAnqi` / `TestParseTaoluWeaponLimitText`。

## 首次修订：按真实兵器限制过滤（历史）

## 问题现象

淬炼（C2S 935 op=5 招式随机洗练）洗双剑时，会洗出**单剑**套路的招式词条，例如日志：

```
recast preview view=121 slot=10 op=5 config=ssword_60501 cost=20000 guanyin=993431111 candidates=[16935 9881 16110]
```

双剑（ssword_60501）本应只洗出兵器限制为「双剑」的套路（如两仪剑法），而不是把所有名字带"剑法"的套路混在一起。

## 根因

旧实现按**套路名关键词**归类武器类别：

- `recastSkillWeaponClass(105)` 把 102(单剑)/105(双剑)/122(重剑) 都归成「剑」；
- `classifyTaoluWeapon` 按套路中文名关键词（含"剑"→剑、含"刀"→刀…）匹配候选。

两步都只是名字猜测，单剑/双剑/重剑互相混淆。

## 修复方案：直接读招式的兵器限制声明

不再猜名字，改用客户端同源的数据链——每个招式的 `skill_new.ini` 条目自带 `UseLimit=` 字段，指向 `skill_use_limit.ini` 里的使用条件（id → 必需武器 ItemType 列表，如 `[5]` → 双剑=105）。服务端已有 `itemdata.UseLimitCatalog` 解析这张表。

### 数据链

```
skill_new.ini (ConfigID 的 UseLimit=5)
  → skill_use_limit.ini ([5] NeedWeaponType=105)
  → itemdata.UseLimitCatalog.NeedWeaponTypes [105]
```

### 实现（cmd/protocol-probe/weapon_recast.go）

- `recastWeaponGate`：惰性加载 `skill_use_limit.ini` + `skill_new.ini` 全部技能的 UseLimit 字段映射（skill_new.ini 约 1.7MB，仅首次加载一次）。资源缺失时降级为「不过滤」，绝不因数据表缺失禁用淬炼。
- `recastPackWeaponTypes(gate, skills)`：合并一个 skillpack 内全部目标技能的 NeedWeaponTypes；第二返回值 false 表示该 pack 没有任何兵器限制声明。
- `rollSkillRand` 约束 2 由「套路名关键词匹配」改为「NeedWeaponTypes 精确包含当前武器 ItemType」：
  - 无兵器限制声明的套路（如太极剑 CS_wd_tjq01）在持特定武器淬炼时**排除**（用户明确要求"直接根据招式的兵器限制来"）；
  - weaponType=0（无武器上下文）时跳过该约束。
- `recastSkillWeaponType(loot, item)`：武器本体取自身 ItemType；防具/护腕淬炼取**身上主手武器** ItemType（对应官方护腕出徒手词条的行为）；无武器=0。
- 删除 `recastClassMatches` / `recastSkillWeaponClass`；`classifyTaoluWeapon` 保留（GM 词条目录分组仍用）。

## 验证

- 单测（weapon_recast_test.go）：
  - `TestRollSkillRandOfficialConstraints`：weaponType 102/107/106/0 各场景；
  - `TestRollSkillRandDoubleSwordUsesRealWeaponRestriction`（回归）：双剑(105) 只出两仪剑法词条、单剑(102) 只出太极剑系、无限制声明不参与；
  - `TestRecastSkillWeaponTypePrefersHeldWeapon`：护腕淬炼取身上武器。
- 真实数据探针（已删除）：skill_use_limit 543 段、skill_new 3545 技能；ItemType=105 合并出 111 个候选 pack，全部为纯双剑限制套路（两仪剑法×10、七星剑×5、九宫剑法×8 等）。
