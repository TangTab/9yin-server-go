# 玩家武器外形显示修复

日期：2026-08-01  
适用服务端：`E:\9yin-go-server2`

## 问题现象

角色已在装备栏的主武器槽 `22` 装备双刺 `sthorn_wyjt_60701`，战斗也按
ItemType `106` 结算，但场景内人物没有显示武器模型。

该装备的已验证资源数据为：

| 字段 | 值 |
| --- | --- |
| ConfigID | `sthorn_wyjt_60701` |
| ItemType | `106`（双刺） |
| 模型 | `sthorn_ywf_002` |
| ActionSet | `6h` |
| WeaponMode | `hand2_1` |

因此不是资源缺失、装备未穿戴或武器类别错误。

## 原因

此前服务端只发送了 NPC 视觉字段：

```text
WeaponName = sthorn_ywf_002
WeaponMode = hand2_1
ActionSet  = 6h
```

这条路径只适用于 `Type=4` 的 NPC。现代 `FxGameLogic` 中
`ShowSceneObjStep2` 在 Type=4 分支读取 `WeaponName` / `WeaponMode`。
本地玩家却是 `Type=2`，所以即使这三个字段已经随 `0x0D` 到达，也不会调用
玩家模型的武器挂接逻辑。

玩家使用的是另一条原生 C++ 路径：

```text
玩家对象属性 Weapon
  → RoleComposite::PlayerVisPropChange(actor2, player, "Weapon")
  → FxGameLogic sub_119E58C0 的 Weapon 分支
  → sub_11007397（玩家 Actor2 武器刷新）
```

解密 Lua 的装备预览、时装预览也明确以 `client_player:QueryProp("Weapon")`
作为玩家武器模型来源；它不是 `WeaponName`。

## 修复内容

服务端新增协商属性：

```text
索引：236
名称：Weapon
类型：string
值：sthorn_ywf_002
```

并在两个时机同步：

1. 玩家首次进图与 `0x0C` 切图后的 `0x0D PlayerAddObject` 中写入 `Weapon`；
2. 装备穿脱后的普通 `0x10 SERVER_OBJECT_PROPERTY` 中再次写入 `Weapon`。

`WeaponName`、`WeaponMode`、`ActionSet` 暂时仍保留，以兼容已有场景通用属性表；
但玩家是否显示武器以 `Weapon` 为准。

## 改动文件

| 文件 | 修改目的 |
| --- | --- |
| `cmd/protocol-probe/main.go` | 将 `Weapon`（索引 236、string）加入 0x09 可见属性表。 |
| `cmd/protocol-probe/player_actor.go` | 初始 0x0D 玩家对象写入 `Weapon`。 |
| `cmd/protocol-probe/equip_gear.go` | 准备装备外观时生成 `Weapon`，换装 0x10 也同步。 |
| `cmd/protocol-probe/appearance.go` | `roleVisual` 保存玩家武器模型。 |
| `cmd/protocol-probe/main_test.go` | 断言协商属性表包含 `Weapon`，总数为 237。 |
| `cmd/protocol-probe/player_actor_test.go` | 断言初始 0x0D 含 `Weapon=sthorn_ywf_002`。 |
