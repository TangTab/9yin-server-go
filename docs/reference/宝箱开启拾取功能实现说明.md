# 宝箱（BoxNpc）开启拾取功能实现说明（2026-09-08）

## 需求
世界场景的宝箱（如洛阳 gathernpc_creator 生成的"镀银宝箱" BoxNpc10006）：
- 点击**不弹 交谈/告辞 对话框**（原先点"交谈"还会报
  `has no cinematic service for func_id=860000001`）；
- 玩家动作切换到**蹲下拾取**；
- **箱子模型变成打开状态**；
- 弹出**拾取框**（View 80 form_droppick），内容 = **随机装备 + 礼包**；
- **拾取完箱子删除、模型消失**。

## 资源实证（实现依据）
1. `share/npc/npcconfig/worldnpc/funnpc/boxnpc.txt`（模板行 BoxNpc10006）：
   - `OpenAction=interact041`（采集动作名 → 玩家 State@19 可直接播放的蹲下拾取）
   - `DelayTime=5000`、`DropID=comd_drop_taskitem_xiakexing_03`、`DestoryTime2=900`
2. 箱子模型动作集：从正式客户端 `res/obj_item.package` 用 PCK0_Decoder 解包
   `obj/itemnpc/itemnpc586/action.ini`（586~591 各宝箱共用）：
   - **`diedown` = open.xskt（开盖过渡）**
   - **`diedownloop` = openloop.xskt（开盖保持）**
   - `close/closeloop` = 关盖；`Tpose` 默认
3. View 80 拾取框与 C2S 380 拾取链路沿用既有 `drop_loot.go`（小怪死亡掉落同一套）。

## 服务端实现（H:\9yin-go-server2）
### 新增 `cmd/protocol-probe/chest_loot.go`
- `isChestNPC`：ScriptClass=BoxNpc 或 ConfigID 前缀 boxnpc。
- `beginChestLootSessionLocked`（sceneLifecycle 方法，点击宝箱入口）：
  1. `chestOpened` 去重（重复点击忽略）；
  2. 玩家播 `interact041`（playerActionStateFrame，State@19 通道，同挖矿）；
  3. 箱子播 `diedown`（objectNativeActionFrame）+ `diedownloop`
     （objectActionStateFrame）→ 模型保持打开；
  4. 回调注入的 `openChestLootView` 打开 View 80；
  5. 2.5s 后玩家回待机站姿（gen 守卫）；
  6. `scheduleMechanismRemoval` 900s 兜底删除（对齐官方 DestoryTime2）。
- `rollChestLoot`：**随机装备 x2**（equipment.ini 里 EquipType 非空的全部
  装备均匀随机，带 ItemType/EquipType/ColorLevel/Level/耐久元数据）+
  **随机礼包 x1**（tool_item.ini 全部 BoxItem 礼包中，只抽 DropID 在
  drops_mvp.json 有正文的——保证拾取后右键能开出内容；礼包目录 14300 条）。
  全空时兜底 yaopin_00100/00300。
- `openChestLootDrop`：关旧掉落窗 → 塞战利品 → encodeDropOpenFrames 开窗 →
  在 playerLoot 登记 `chestPending{world, entityID, ownerID}`。
- `removeUsedChest`：锁内删实体（defeated 墓碑 + scene.Remove + 清
  entities/combatActors/combatStates + reconcileViewportLocked），与
  scheduleMechanismRemoval 定时体一致；同时清 chestOpened 标记。

### 挂点
- `scene_lifecycle.go objectRequest`：在 isMineNode 之后新增宝箱分支
  （世界场景点击才走这里；副本/暮色宝箱由 clone/twilight 处理器先行
  拦截，互不干扰）。新增字段 chestGen/chestOpened/openChestLootView。
- `main.go`：注入 `world.openChestLootView`（拿当前连接的 link/loot）。
- `drop_loot.go`：playerLoot 增加 `chestPending`；`handlePickupDropCustom`
  的"drop empty closed"分支回调 `pending.finish()` → **拾取完立即删箱子**。
- `internal/drop/catalog.go`：新增 `HasPackage(dropID)`（礼包内容校验）。

## 游戏内验证要点
1. 到洛阳宝箱处点击 → 不弹对话框；玩家蹲下（interact041），2.5s 后站起；
2. 箱子模型开盖并保持（diedown → diedownloop）；
3. 屏幕出现拾取框：2 件随机装备 + 1 个随机礼包；
4. 拾取完最后一格 → 拾取框关闭 + **箱子模型消失**；
5. 未拾取 900s 后箱子也会消失；重复点击已开的箱子无反应。
日志关键词：`chest begin` / `chest ... drop opened slots=3` /
`chest id=... removed after loot`。

## 备注
- 随机装备池是全量 equipment.ini（各等级都有）；如想限制等级段/品质，
  在 `chestEquipmentPool()` 加过滤（如 `d.Level <= 60` 或按 ColorLevel 加权）。
- 礼包开出内容取决于 drops_mvp.json 里对应 DropID 的正文（与礼包使用
  流程一致）；如需指定某几个礼包，把 `rollChestLoot` 的礼包段改成白名单。
