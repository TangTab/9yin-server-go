## 三、已完成工作明细

### 1. 目录初始化（脚手架）

- `go.mod`（module github.com/lizhanyin/9yin-server-go）+ Makefile + .gitignore 补充
- `cmd/`：solo（首载体）、entry/lister/member/world/public（二期桩）、probe（对拍客户端桩）
- `internal/` 14 包骨架，doc.go 固化各包职责与依赖边界
- `tools/`：structgen、protogen 桩
- `testdata/`：struct 全量副本（208 XML）、lua 全量（361 脚本，含九阴血统的门派/江湖死代码）、
  lua-bootstrap（36）、ini 抽样 + scenes.xml + logic_class.xml、captures/ 占位
- GOPROXY 全局切 goproxy.cn（默认代理网络不可达）

### 2. ECS 内核（internal/ecs，~450 行，零仓库依赖）

- EntityID：index 32b + generation 32b，句柄防悬挂（NullEntity=0 永不签发）
- sparse-set Storage：swap-remove 紧凑；**每实体组件版本号**（Set 自增、swap 随行）
  ——sync 层脏检测地基
- World：CRUD（Add/Get/Set/Remove/Has/Version/Count/EntityCount）+ Each1/2/3
  快照遍历（回调内增删改销毁安全，缓冲 sync.Pool 复用）
- Scheduler：按序执行、帧号推进、重名启动期 panic
- 测试 7 项全绿；BenchmarkEach2：10000 实体/5000 匹配 63.5µs/tick（~12.7ns/实体）

### 3. structgen（tools/structgen，~500 行）

- 容错解析链：GBK 转码 → 剥非法注释 → 补未引号属性 → XML 解码
- 类型映射含 object→ecs.EntityID；全路径分段驼峰命名 + 全局去重
- 产出：13 个生成文件（12 组 + meta/注册表），元数据含 public/private/save/realtime
- 数据侧修正（见 testdata/README.md「本地修正记录」）：
  - `player/PetShow.xml:166` 注释体 `--` 非法 → 改等号线
  - `rule/transtool.xml:18` `maxrows=1` 未引号 → 补引号
  - 保留警告：struct_template.xml include 的 rule/fight.xml 在此分支不存在（数据层差异，不改）

### 4. config / proc / engine

- config：Row 辅助方法（Str/Int/Bool/CSV，CSV 过滤原版空段写法）；
  scenes.xml 场景表（**ID 为 string**——存在 "202_1" 变体写法）；
  logic_class.xml 类型树（嵌套解析 + IsA 继承链判断）
- proc：Bus 接口（Publish/Subscribe/Close）+ InprocBus（同步直投、Topic 精确 +
  "*" 广播、顺序保证、关停语义）——solo 先用，TCP 实现后业务层零改动
- engine：App（World+Scheduler+Bus 装配）、OnStart/OnStop 钩子、
  TPS 定帧/全速双模式、ctx 优雅停机、TickOnce 测试驱动
- solo 骨架端到端：`配置就绪：50 场景（副本 32）、101 逻辑类（根 9）`，60TPS 稳定

### 5. net（本轮，internal/net）

线路层移植与能力重构（对拍结论见分析报告第八章）：

- **帧/码正交**：Framer（EscapeFramer=EE 定界 / PrefixFramer=4B 长度前缀）
  × Cipher（XorCipher / IdentityCipher）自由组合
- **键注入**：Key 运行时注入/轮换（SetReadKey/SetWriteKey 方向独立）
- **前缀式内部协议**：PrefixFramer 对应黑金 FsComm 内部帧形态，proc 总线线路层就绪
- **代码生成器接缝**：Framer/Cipher 接口供 protogen 产物组装（对应原版 FsVerEnc）
- 旧分支 transport 的 EE 转义/终止/错误语义逐字节保留；EncodeFrameBody 留作 golden 对拍
- 8 项测试全绿（含键轮换、明文线路观察、200 帧并发）

## 四、关键决策记录

| 决策 | 依据 |
|---|---|
| ECS 化而非照搬 OO | struct XML 属性包与组件模型天然同构；并发分片与脏同步受益 |
| 客户端线路用 EE+XOR（非黑金前缀帧） | 目标是九阴现代客户端；黑金 CJ 分支反汇编证实其基线无 EE/XOR，编码为可选可插拔层 |
| 场景 ID 用 string | 原版存在 "202_1" 变体后缀，int 建模失真 |
| component/ 只放生成物 | 单一事实源不被手改污染，随时可删重建 |
| 格式知识不进 Lua | probe 发现 → 规格文件记载 → 生成器落码 → golden 锁死；Lua 只承载行为 |
| 原版数据直读（NINEYIN_DATA） | 生成器可直读原版目录不拷贝；testdata 快照兜底保证仓库自包含可构建。已验证两条路径产物逐字节一致 |
| lua 死代码保留（jn_menpai/jn_jianghu） | 九阴血统的技能脚本写法样本，对本项目价值最高 |
