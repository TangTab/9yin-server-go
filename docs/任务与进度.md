### 8. svrlist 区服列表分发（本轮，internal/login/lister.go）

login 链第一环（连接 → 认证 → **区服列表** → 选角 → 进场景）：

- **方言**（golden 钉死 testdata/captures/svrlist-{request,response}.bin，
  旧分支 loopback-lister 对官服系方言的实测转录）：独立于 EE+XOR 游戏
  线路的**明文 ASCII 行协议**——请求 `svrlist\n`；应答
  `$svrlist #\uXXXX名 $通告地址 端口 尾标\r\n`（名字 \u 转义=大写十六进制
  UTF-16 码元、增补面拆代理对；`#`/`$` 前缀与尾标语义未证，按对拍原样保留）；
  应答后断连，一连接一请求
- **判定**：golden bin 入库时 CR 被 git 文本规范化洗为 LF；实证可用形态
  （PS1，真实 fork 客户端接受过）应答结尾 CRLF，以 CRLF 为准
- **Lister**：accept → 读行（\r/\n 皆可，PS1 同款宽容）→ 编码应答 → 断连；
  `EncodeServerList` 纯函数对拍入口；多条目分隔方言未知不发明
- **cmd/lister** 从桩升级为独立载体（替代旧分支 loopback-lister.ps1，
  -addr/-name/-host/-port 可配）；solo 内嵌 `-svrlist`（默认 127.0.0.1:9601，
  通告地址/端口自动跟随 -listen）
- probe `-svrlist` 模式：golden 请求 + 方言断言（头/字段数/$ 前缀/CRLF）
  + `\u` 名字还原打印
- 测试 6 项：编码 golden、转义（含代理对）、真 TCP 往返、\r 请求容忍、
  Close 幂等、通告推导；实跑 solo×probe 与独立 lister×probe 双路 PASS

### 9. 登录首段（本轮，internal/login/{auth,flow}.go）

login 链第二环——账号登录方言落地，golden = 首飞线路帧：

- **golden**：`testdata/captures/login-connect-001.bin`（旧分支
  connect-first-flight.bin 转录，123B XOR+EE 完整 wire 帧）。解码关键：
  末尾 `d5 83` 是 XOR 过的 `EE EE` 终止符（EE^3B/EE^6D），解帧后 121B
  明文 op02 四槽结构恰好收尾——线路层与登录结构两层方言一次钉死
- **op02 结构**（auth.go）：25B 头 + account 槽（16~256，%16）→
  password 槽（16~512，%16）→ client-type u32 值 → login-string 槽 →
  login-type u32 **恰好帧尾**（拒绝尾部数据）。身份 =
  sha256("nineyin/login-account/v1"·NUL·len·account 槽) = `acct:v1:<64hex>`，
  golden `acct:v1:112cd36f…`（密码槽变更不改身份——多端改密不改键）
- **应答方言**（flow.go）：op02 → 无角色 0x04 ServerPlayerRoles
  （41B：status=1 @0x01 + 年/月/日/时/分/秒 u32 @0x09..0x1D）；
  op03 → 0x05 worldInfo（u16 type + UTF-16LE+NUL，五书开放串）；
  非法登录结构拒答断连（旧服同口径）
- **Flow**：Gateway.OnFrame 第一接入点，Clock 可注入；OnLogin 回调
  留账号域挂点；solo 0.4.0 接线
- probe `-login` 模式：解码 golden 首飞→重放→断言 0x04（含年份合理性）
  与 worldInfo；实跑 PASS（服务器时间/身份前缀/五书串全对）
- 测试 6 项（身份 golden/密码突变稳定/坏结构拒绝/0x04 布局/worldInfo
  布局/网关端到端），login 包累计 16 项全绿

### 14. CReactor 网络引擎复刻（本轮，internal/reactor）

官方 Fs 框架 CReactor（FsSoloLister.dll 等 IOCP 引擎，map 符号实证）
的 Go 复刻——**复刻架构语义而非 syscall**（Go Windows netpoller 本身
就是 IOCP，逐字移植=重写运行时）。对齐表见包文档：

- **三通道**：CreateListener（AcceptEx）/CreateConnector（ConnectEx
  异步拨号，失败仅记日志停留 connecting 态）/CreateBroadcast（UDP
  广播收发一体，Go 对 DGRAM 默认 SO_BROADCAST，单口双收=官方双口等效）
- **EventLoop 单线程派发**：所有回调按投递序串行（官方语义，业务侧
  免锁）；缓冲满另起协程兜底，回调绝不丢弃
- **identity 校验**：id 单调永不复用，陈旧/伪造 id 一律拒发
  （官方 ProcessRead/Write/Connect/Broad "identity error" 同效）
- **Send**：异步入队（官方 PostQueuedCompletionStatus），每连接有界
  发送队列 4MB（官方 ExpandOutBuffer 无限扩容→护内存改为拒发+日志）
- ShutdownConnector/CloseConnect/GetConnected/Stats（DumpReactor 语义）
- 测试 5 项×3 连跑全绿（回环 echo/串行派发/陈旧 id 拒绝/广播自收/
  Stop 排空幂等）；实机冒烟：**127.255.255.255 真网段广播自收 ✓**
- 用途：分布式形态（lister :15000 注册通道、进程间总线）的网络底座，
  规格=docs/分布式形态清单.md；现有 gateway/login 线路不动

## 四、关键决策记录

| 决策 | 依据 |
|---|---|
| ECS 化而非照搬 OO | struct XML 属性包与组件模型天然同构；并发分片与脏同步受益 |
| 客户端线路用 EE+XOR（非黑金前缀帧） | 目标是九阴现代客户端；黑金 CJ 分支反汇编证实其基线无 EE/XOR，编码为可选可插拔层 |
| 场景 ID 用 string | 原版存在 "202_1" 变体后缀，int 建模失真 |
| component/ 只放生成物 | 单一事实源不被手改污染，随时可删重建 |
| 格式知识不进 Lua | probe 发现 → 规格文件记载 → 生成器落码 → golden 锁死；Lua 只承载行为 |
| 原版数据直读（NINEYIN_DATA） | 生成器可直读原版目录不拷贝；testdata 快照兜底保证仓库自包含可构建。已验证两条路径产物逐字节一致 |
| lua 死代码保留（jn_menpai/jn_jianghu） | 九阴血统的技能脚本写法样本，对本项目价值最高 |
