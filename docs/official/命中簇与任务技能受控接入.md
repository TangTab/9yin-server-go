## 一、命中簇

### 1.1 要不要发受击帧：招式表 `Stagger`

官服对受击者发不发受击帧由**招式表的判定触发器**决定，与技能本身无关：

| 判定帧的触发器 | 受击反应由谁播 | 官服 | 产物 `Stagger` |
|---|---|---|---|
| `trigger_hitbreak;帧;动画` / `trigger_hitback;帧;距离,动画` / `hitdown` / `hitout` / `hitclasp` | 客户端按招式表自播 | 不发任何受击帧 | 0 |
| `trigger_hitbreak;帧;,`（不带动画） | 服务端下发 | 发受击帧 | 1 |

证据：女号包 `cqgf01` 三拍动画 `hurt_f_2_s / hurt_f_1_s / hurt_f_1_l`，22 次命中零受击帧；
飞镖 `hitbreak;14;hurt_f_1_s` 同。`cqgf04/06`、任务技能 `musejuben_2/4/5` 的触发器不带
动画，命中都有受击帧。`zs_normal_00_01` 两拍均为 0（普攻 65 次命中零受击帧）。

- 构建：`tools/datagen action` 给每个判定时刻聚合「该刻全部判定触发是否都不带动画」，
  写 `Stagger="1;0;…"`（与 `Hits` 逐拍对位）；审计报告多两项
  （`sections_with_stagger_hits` / `stagger_beats`），`-verify` 一并回读比对。
- 装载：`actiondata.Action.Stagger`、`Action.Staggers(index)`；列数不齐或旧产物按
  「不下发」处理。
- 规模：12,770 招里 11,310 招带判定、27,255 个判定触发；5,276 招 / 9,945 拍由服务端发受击帧。

群战包交叉验证：14 个常规武学技能里 10 个符合上表；`CS_jh_xfz02_hide`、`xfz03`、
`sfgp02`、`CS_em_jdmz06` 触发器不带动画却不发受击帧，原因未明（玩家对玩家，与招架态
无关），见 §七。

### 1.2 发什么：技能事件包的抓包复原

发什么由服务端专有的技能事件包决定（逐级属性 `EventProcess`，客户端资源里没有这张
表），只能按抓包复原——`combatreact.go` 的 `hitSpecs`：

| 技能 | Stagger 拍的受击动作 | 受击特效 `m24 40` | 依据（女号包） |
|---|---|---|---|
| `CS_jh_cqgf04` / `CS_jh_cqgf06` | 仅首次交手 | 每击 `body_hit_3_self` | 357.896 首击 `m18+c40`，384.503 / 388.619 只 `c40` |
| `skill_musejuben_4` | 每击 | 无（另有受控，§三） | 731.440 |
| 其余（含 `skill_musejuben_2/5`） | 每击 | 无 | 730.436 / 730.885；群战包常规武学的多数形态 |

`c40` 的名字是特效（`ini/effect/effectcontent/actioneffect.xml` 的 `EffectItem`），各技能
不同，不在客户端表里。未在表里的技能不发 `c40`。

### 1.3 单个受击目标的帧序

```
攻击者 FP → SP（每受击目标一对 +2；已到上限不发）
→ [首次交手：NPC.LogicState=1 → 关系行加行 → 玩家 LogicState=1 → m24 37]
→ 关系行刷新 → m24[目标,17,伤害,…]
   非致死   [受击动作 m18 hurt_half] → [m24 10 / MaxHits] → [m24 40] → [受控（§三）]
   击杀     摘掉目标身上的 buff（逐个 m169 摘）→ 关系行删 → m24 29
            → m18 hurt_half → [m24 10 / MaxHits] → [m24 40] → [m24 13]
→（全部目标之后）m205[攻击者,技能,全部目标…]
```

与旧实现的差别（均以两份抓包为准）：

- **得怒按目标计**：一拍打几个目标就几对 FP/SP（730.436 五目标五对；挑战包 77.273 双杀
  两对）。旧实现每击一对，注释称「挑战包一招双杀只发一对」是误读。
- **连击 `m24[自己,10,n]`**：2 秒窗口内连续命中累计（全包 190 次相邻帧：延续的最长间隔
  1.925s，重置的最短间隔 2.037s），每受击目标 +1，跨招延续（208.741 → 210.666：`cqgf01`
  三击后 1.9s 接 `cqgf04`，连击 3 → 4），第 2 击起发。被闪避打断，此后从 1 起算
  （挑战包 442.392：3 4 5 → 被闪避 → 1 2）；击杀不打断。
- **`MaxHits`** 只在连击数刷新最高纪录时推（首击即推 `MaxHits=1`，其后 1→24 逐次刷新才推，
  平纪录不推）。旧实现从第 2 击起每次都推。
- **闪避**不计得怒、不发 FP/SP（226.276）。
- **击杀摘 buff**：致死一击的 `m24 17` 之后、`m24 29` 之前逐个摘（358.469 摘
  `buf_CS_jh_cqgf01`；757.405 摘 `buf_skill_musejuben_42` 与 `buf_CS_wd_tjq08`）。
- **`m24 13` 不是击杀必发**：两包 31 次击杀里只有 `skill_musejuben_4`（757.405 / 758.416）、
  `skill_musejuben_7`（820.649）、`CS_jh_hyjf07`（挑战包 483.077）带，`cqgf04/06`、普攻、
  `musejuben_2/8`、`hyjf01/03/08`、飞镖的 26 次都不带。触发条件未定，按技能复原
  （`hitSpec.deathMark`）。旧实现每次击杀都发，且排在 `m24 10` 之前。

## 二、任务技能入口 msg270

任务技能（`skill_musejuben_2/4/5/6/7/8/9`，技能道具）由 `m141 + m1[2,"9491",技能]` 下发，
客户端用 **`m270 [技能名]`** 施放——不带坐标与目标。两条入口此后共用 `planSkillCast`
（`skill.go`），`m270` 的差别：

| 环节 | m211 | m270 | 依据 |
|---|---|---|---|
| 位置 / 目标 | 取自报坐标与目标 | 服务端位置；需目标的技能回落最近选靶 | 728.313 `CurSkillTarget` = 当前选中 |
| 闸门顺序 | 出招中 → 冷却 | **冷却 → 出招中** | 722.139 受理 → 722.286 施放中再按 → 722.324 `m1[2,"9009"]`（其前无清扫帧） |
| 冷却中 | 零应答 | `m1[2,"9009"]` | 约 80 次 |
| 无目标 | `m707[9030]` | `m1[2,"9030"]` → `m707[7]` | 722.992 |
| 目标已死亡 | 无 | `m707[9016]` | 742.648 |
| 出招中 | `m707[9033]` | `m707[9033]` | 730.864 |
| 普通技受理帧 | `CurSkillID → [CurSkillTarget] → 冷却行 → MP → 0x1F → m337 → m20` | `CurSkillID → 冷却行 → MP/SP → [自身 buff] → m20`（**无 `0x1F`、无 m337**） | 722.139 / 731.152 / 743.280 |
| 锁定技受理帧 | `… → 0x1F → LastWGHit=100 → m24 40 → m19 → CantMove → CantParry` | `CurSkillID → CurSkillTarget → m284 → 冷却行 → MP/SP → 0x1F → LastWGAttackNpc=目标名 → m24 40 → m19 → CantMove → CantParry` | 728.313 / 769.504 |

结果码 = 9000 + `skill_error_define.lua`：9 冷却中、16 对象已死亡、22 战意不足、
26 空中不可用、30 没有选择目标、33 其他技能正在使用中。

附带的三处修正：

- **战意消耗**：`AConsumeSP` 此前未接。`musejuben_4/7` 耗 35、`_8/9` 耗 25（731.152：
  SP 44 → 9）；不足回 `m707[9022]`。`_2/_5` 耗 MP 7，`_6` 耗 MP 16 + 轻功 10。
- **锁定包动作回落**：`musejuben_6/7/8/9` 的逐级行没有 `Flow` 列，命中动作在锁定包
  （`skill_lock_data`）里——`CS_sl_lhq02` / `CS_jz_xytf06` / `CS_slzp_lzs07` /
  `CS_sl_djgq06`。此前动作名回落成技能 ID，命中根本不结算。`m19` 的技能名位与闪避动作
  统一取锁定包（`HitAction` / `DodgeAction`）；常规锁定技两者与技能 ID 同名，行为不变。
- **施放期间的自身 buff**（`musejuben_4` 的霸体 `buf_fixed_red`）：受理时
  `SP → CantBeSkillLocked=1 → CantBeSkillMustLocked=1 → BufferInfo3 → m169 挂载`，
  收招时 `CurSkillID="" → m169 摘 → BufferInfo3="" → 两个属性位清 0`（731.152 / 738.115）。
  玩家 buff 槽串 `BufferInfoN = "静态包ID,目标对象,own,等级,到期(1601 纪元毫秒),0"`
  （各段大写十六进制），首个 buff 落 3 号槽。

## 三、命中受控：`skill_musejuben_4`「推—拉」

`combatcontrol.go`。命中动作 `CS_wd_tjq08`，判定帧 333 / 6000 / 7934ms，每拍对每个
存活的目标：

```
首击    m169 挂 buf_skill_musejuben_41（击晕 4s）→ m169 挂 …_42（减速 8s）
        目标正在出招：State="hurt_stun_2" → State="" → CurSkillID="" → m189 → m24 56
        目标没在出招：State="hurt_stun_2"（硬直 3s 后 State=""）
        → m169 挂 buf_CS_wd_tjq08（命中硬直 3s）
第 2 拍 m169 重加 41 → m169 摘 42 → m169 挂 42 → [出招中：CurSkillID="" → m189]
        → m24 56 → m24 78[目标,攻击者,"","",N,1e+08] → 推离到离攻击者约 5.3m
第 3 拍 同第 2 拍，拉回攻击者身前约 0.7m
```

- buff 效果在 `share/modifypack/proppack.ini`：6387 = `CantMove/CantUseSkill/CantUseItem`，
  95240 = `RunSpeedAdd -50`，7210（`buf_CS_wd_tjq08`）= 四个 Cant 全 1。这两个任务 buff
  不被任何客户端表引用，挂在服务端专有的 `EventProcess` 包上。
- **N 是该目标自出生以来被击退的累计次数**（重生归零）：同一瞬间五个 NPC 朝不同方向被
  击退 N 全为 1；`35000160` 连续 8 次为 1~8；`350001de` 中途死亡重生后归零。
- **打断**：出招对象清空、序号推进让余击落空（同 `breakFlow`）。被打断的起手不会再走它
  自己的收招回调（那里才重排决策循环），硬直接束时由受控逻辑把 NPC 放回决策循环；
  硬直期间 `npcThink` 不动手。
- 击退在途服务端位置不动，到位后落位；推离后朝向转为运动方向，拉回不变。

## 四、位置同步：AllDest 记录

`0x21`（明文）与 `0x2C`（QuickLZ 压缩）是**同一种 44 字节记录**：
`obj, own, 目的地 xyz, 朝向, 速度, 旋转, motion2, motion3, 移动标志`——即
`entergen.ServerAllDestFrame` 的条目。击退用它的明文形态：

| 记录 | 速度 | 旋转 | motion2 | motion3 | 标志 | 时机 |
|---|---|---|---|---|---|---|
| 推离·移动 | 2.0 | −2π | 4.0 | 8.0 | `0x2602` | 击退瞬间（当前位） |
| 推离·停止 | 0 | 0 | 4.0 | 8.0 | `0x0a` | 约 0.85s 后（终点） |
| 拉回·移动 | 8.0 | −2π | 7.8 | 30.4 | `0x2602` | 击退瞬间 |
| 拉回·停止 | 0 | 0 | 7.8 | 30.4 | `0x0a` | 约 0.25s 后 |

`TestAllDestRecordMatchesOfficialBytes` 用官服两条帧（757.405 / 758.248）的原始字节
按布局拆回条目、再用服务端编码器重编，逐字节还原。官服在到位后有时再补一条标志
`0x600` 的停止记录，本实现未发。

## 七、未覆盖与已知偏差

1. **真机未验**：全部帧序只对过抓包。
2. **NPC 招架玩家**未接：`bossborn003003` 招架时 `m24[目标,8,1,…]` 后伤害减半（731.440）。
3. **长招途中脱战**：最后一次战斗活动 3 秒后玩家脱战、5 秒后关系清空（既有规则）。
   `musejuben_4` 的第 1、2 拍相隔 5.7 秒，期间没人打玩家就会脱战——抓包里玩家一直被打，
   官服对「出招中是否算战斗活动」无证据。
4. **闸门未接**：受击硬直中 `9023`（定义文件无此码）、空中 `9026`——玩家的受击态与空中态
   尚未跟踪。
5. **按技能复原、无通用判据**：受击动作是否每击、`c40` 特效名、击杀是否带 `m24 13`、
   命中受控——都在服务端专有的事件包里。现有技能之外的新技能走缺省（Stagger 拍每击
   `m18 hurt_half`，无特效、无受控）。
6. **击飞 `c79`、击倒**未接：PvE 抓包里没有样本（只在群战包的玩家对玩家里出现）。
7. `musejuben_4` 的伤害与官服不同（本实现 1166，官服 226；`musejuben_2` 250 对 243）——
   属伤害公式引擎，本篇未动。
8. 玩家 buff 槽串只接了「施放期间自身 buff」一种来源；3 号起始槽位只有两例证据。
9. 群战包里 4 个触发器不带动画却不发受击帧的玩家对玩家技能，原因未明。
