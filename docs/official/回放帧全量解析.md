## 一、容器与解析纪律

- 打包格式 = `[u32 len][frame]×N`（`replayFramesPack` 逐帧回放；exe 内嵌
  `replaydata.Phase1/Phase2` 与 tmp bin 同源）。
- 每帧解码**必须恰尽帧体**（残差即报错）；全量结果：
  - P1：13 帧中 11 帧严格恰尽，2 帧 LZ 池种子缺失（见 §三）；
  - P2：322 帧中 321 帧严格恰尽，1 帧（#83 0x2A）官方池尾越界。

## 三、LZ 池与三帧不可解

- 池模型 = `World2`（fxnet2 解压器：4096 槽全局池 idx=((v>>12)^v)&0xfff，解压
  输出+非族帧明文滑窗注册）。
- **P1#0 / P1#6 / P2#83 官方池也解不开**：它们在原流里依赖更早官方帧喂池
  （登录爆发区/0x09 大表），瘦身 bin 丢了前缀——「LZ 精确重放不可行」结论
  复核成立（外服压缩值消息族 0x27-0x2a 全景 §三）。生产上透传原样字节，
  客户端自带同款池状态可直接解（真机渲染正常为证）。
- 0x2A ×14 帧本池失败、**原流前缀喂池后全部可解**（交叉解码）：内层 = ViewAdd
  `[obj u16][own u16=槽][row u16][181/1942][08]…`，装备槽行（helmet_60705/
  cloth_50704/pants_50704/…，own=0x001e..0x0022 槽段）+ 两帧武器（obj=0x0079
  ShortWeapon/sword_40403/sthorn_40405）。→ DROP-8 停发处置维持。

## 五、两案根因与修复（本次落地）

### 1）「保存的按键配置的下发有问题」

- 官方通道定案：外服在**化身 0x28 档案 f#042 idx198 ShortcutKey**（str176
  '1,87;2,83;…'，与 195 上传同串形）交付键位；外服抓包**全程零 0x10 idx198**。
  外服家族客户端在 AddObject 时从档案字段初始化键位管理器——后到的 0x10
  单属性帧只同步属性视图（保存面板），不重建引擎键表。
- 我方缺口：`playerProfile0x28Frame` v1 刻意省略 ShortcutKey（当时按
  「主段+增量续段=未验证形态」回避——后经解析定案：续段是 LZ 编码器字典
  复用手法，语义即完整串；0x46 明文单段=标准编码）。
- 修复：`player_profile_0x28.go` 增 `keybind` 参数，把存档 scheme0 串
  （195 上传原串+NUL）嵌为尾字段；三处调用点（native P1#6 换代/swap-self/
  常规进场）接 `player.keybindSnapshot().bind`。0x10 推送簇照旧（兜底）。

### 2）「角色的运动模式被设置为走路模式（默认应跑步）」

- 引擎侧定案（fxgamelogic_rebuilt.dll 程序反推）：
  - `move_type` 引擎态：**0=跑 / 1=走**；role 创建默认 0=跑（0x46eb782）；
  - 建视觉体判定（0x46eaa00）：实测速度>2.0→move_type=0 跑，≤2.0→1 走；
  - 轻功检测（0x504cb30）：无 buf_qg_fast → qinggong_id=0 + move_type=0（跑）；
  - 切换键（0x411de35）：ui_walk_to_run/ui_run_to_walk 翻转。
  - 0x09 表 **idx1829 IsRun(t3)** = 服务端声明通道（官方抓包未见显式下发，
    引擎缺省即跑）。
- 我方根因：外服位序 = **物理档案流（34+ 条速度/跳跃族单属性 0x10）在
  0x0B 进场之前**（c.pcapng #12..#40，含 WalkSpeed/MoveSpeed）；瘦身 bin
  Phase A 从 #110 起——速度族全落 Phase B 镜像段，而化身建视觉体在 Phase A
  已发生 → 速度缺省 0 ≤2.0 → **move_type=1 走路**。PHYSICS-16 的显式 0x09
  后补发晚于判定沿。
- 修复（双管）：
  1. **PHYSICS-17**：native 帧替换档下 Phase A 发送前（0x0B 之前=外服同位，
     登录爆发区非读条窗口）前置整条 `sendPlayerPhysicsLoginStream`；
  2. 物理档案流尾增 **IsRun=1**（idx1829 显式跑步态，InteractStatus 同族
     「客户端缺省 0」兜底）。
- 既有 MOTION-15（Phase B 镜像帧就地改写）与 PHYSICS-16（0x09 后补发）保留。
