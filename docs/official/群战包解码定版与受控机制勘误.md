# 群战包解码定版与受控机制勘误（2026-11-25）

> 数据源：`E:\Game\9yin\9yin-server-go2\资料\群战.pcapng`（**7071 线**，观测端 `0e0c16d0`
> 全程不参战，824 秒 / 22,752 事件；58 个施法者、329 次出招、451 个命中节拍）。
> 属性表用仓库内嵌的官服 2433 表（`internal/clientdata`，包内无登录阶段 `0x09`）。
> 对照包：女号包（8032 线，玩家打 NPC 的任务技能段）。
>
> 结论先行：
> 1. **State 是字符串**。《击飞击退击倒机制规格书》的「State 整型态 6/12/13 状态机」
>    是把字符串长度前缀当整数读的解码伪影；`c78` 的 N 是叠加计数，不是方位角。
> 2. **受控者的位移经 `0x2C`（QuickLZ 压缩批量位置帧）广播给旁观者**，`0x21` 意图帧
>    在受控窗口里几乎为零。规格书「旁观者零位移流」不成立（它的解码器看不到 `0x2C`）。
> 3. 受控帧族布局本身仍有效：`c56` / `c78` / `c79` / `m18` 的线型与规格书一致。
> 4. 受击反应**按技能配置**；多段命中节拍与招式表判定帧逐拍吻合（独立服务器验证）。
> 5. 本分支（`internal/fssoloworld`）没有受控、没有 `0x2C` 编码器、没有任务技能入口 `m270`。

## 一、解码链

`tools/pcapevents`（`dumpall`）本轮补齐，对既有行格式只在**行尾追加字段**或新增行：

| 帧 | 布局 | 说明 |
|---|---|---|
| 属性表 | 包内登录阶段 S2C `0x09`；缺席时回退内嵌官服 2433 表 | stderr 打印来源；群战包 7,151 条 `0x10` 零坏值 |
| `0x1F` | `[obj][own][x][y][z][朝向]` | 单对象位置（行尾追加字段） |
| `0x21` | `u16 条数 + 条数×44B{obj,own,目的地 xyz,朝向,速度,回显槽×3,移动标志}` | 移动意图 |
| `0x2C` | `2c 47 …`：`[0x47]` 起是 QuickLZ 流 → 明文体 `[u16 条数][44B{obj,own,x,y,z,朝向,…}]` | **多对象当前位置**；群战包 839 帧解出 774，余 65 帧为抓包缺口坏流 |
| `0x2D` | `2d | u16 对象数 | 每对象{obj,own,u16 属性数,{下标 u16,值}…}` | 多对象属性（值编码同 `0x10`）；2,029 帧全解 |
| `NINEYIN_PCAP_HEX=<n>` | 环境开关 | 未解码帧追加原始 hex 头与 `0x47` 明文体长度（缺省不开） |

解压器直接用 `internal/fssolorobot` 的 `QLZDecompress`（官方 `qlz_decompress` 的复刻）。
注意：`0x47` 帧压缩流里的字节是 LZ 匹配数据，**不能当明文读**，必须先解压。

`tools/pcapevents/combatscan.py` 在 `dumpall` 文本上做结构化扫描：

```sh

python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt skills     # 按招式聚合：出招/命中节拍/施法者位移
python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt hits       # 命中时受击者收到的帧（按技能）
python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt control    # 受控逐例：恢复时长 + 位置轨迹 + 0x21
python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt push       # c78 的 N 对照位移方向（方位角假说检验）
python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt stacks 735 800 0x350001de   # N 与受控 buff 加减对齐
python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt track 1.967 0x0e03df69 0.3 2.8   # 单对象逐帧轨迹
python -I -X utf8 tools/pcapevents/combatscan.py qunzhan.txt cast 3.499 0x0e0c112d          # 一次出招的时间线
```

（`-X utf8`：管道输出按 UTF-8 写，便于用中文关键字过滤。）

## 四、受控

### 4.1 State 的真实取值（全 394 条推送）

`stand`×134、`""`×82、`walk`×80、`interact041`×24、`interact035`×22、
**`hurt_stun_2`×12**、**`hurt_spitout`×11**、`run`×9、`offact455`×9、`offact456`×8。
线上是「u32 长度 + 串」：`b7 00 | 06 00 00 00 | 73 74 61 6e 64 00`（下标 183，`"stand\0"`）。

| State | 语义 | 证据 |
|---|---|---|
| `hurt_spitout` | 击飞态 | 与 `c79 "hurt_f_1_l"` 同毫秒；恢复中位 0.93 秒（0.06～3.08） |
| `hurt_stun_2` | 击晕/硬直态 | `wuji_CS_wd_tjq08` 等命中；恢复中位 2.62 秒（0.06～3.30）；女号包一例 5.72 秒 |
| `interact0xx` / `offact4xx` | 交互 / 空闲动作 | 与战斗无关 |

### 4.2 击飞轨迹（群战包 1.967s，玩家 `0e03df69`）

```
+0.000  c56 + c79[攻击者,"hurt_f_1_l"]       地面 y=13.23
+0.188  c56 + c78[攻击者,"","",5,1e+08]      击退
+0.262  0x2C  291.69,13.23,918.38            水平 2.56 米，高度不变（击退滑行）
+0.739  0x2C  287.30,13.23 → 287.30,15.59    开始上升

+1.317  0x2C  287.65,16.77,917.26            停在顶点
+1.532  0x2C  289.98,16.77,912.84            空中被横向推开 4.5 米

+2.432  0x2C  290.55,13.43,911.75            落地
```

- 33 例受控窗口里 `0x21` 意图帧几乎为零（仅 1 例 2 条）；位置全部来自 `0x2C`，
  采样间隔不规则（0.15～0.5 秒），不是固定节拍。位移由谁计算（受控者客户端自驱后上报，
  或服务端模拟）从旁观包无法区分；对旁观者的协议面相同：服务端经 `0x2C` 下发位置。
- 女号包同款：NPC `350001e8` 被 `c78` 后 `0x2C` 把它推到水平 5.0 米外，高度不变；
  击退结束后 NPC 自己走回玩家身边（取「最后一个采样」会把回程当成击退方向）。
- 帧内只有攻击者对象、没有方向向量；干净个例里位移沿「攻击者→受击者」连线背离攻击者。

### 4.3 `c78` 的 N 是叠加计数

- 女号包（单攻击者）每个受控 NPC 的 N 序列：`35000160: 1 2 3 4 5 6 7 8`、
  `350001de: 1 2 | 1 2 3 4`、`350000fe: 1 2 3 4`……每次击退 +1。
- 同一瞬间五个 NPC 朝不同方向被击退（43° 与 149°），**N 全为 1**；
  N 与位移方位角相关系数 −0.08（19 例）。
- 重置发生在受控 buff 完全过期之后（`350001de`：742 秒掉光、34 秒后再受控 → 回到 1；
  797 秒掉 buff 仅隔 1.7 秒再被打 → 继续累到 3、4）。精确重置规则未定。
- 群战包同一玩家连续两次 `c78` 为 5 → 6；其余 14 / 68 / 109 / 119 / 167。
  首次击退恒为 1。

## 六、对《击飞击退击倒机制规格书》的勘误

| 规格书 | 实际 |
|---|---|
| §二 State(183) 整型态：1 常态 / 4、5 落地 / 6 腾空 / 12 倒地 / 13 浮空 | State 是字符串；1/4/5/6/12/13 = `""`/`run`/`walk`/`stand`/`interact0xx` 等串的字节长度 |
| 「击倒 = State 6→12 同毫秒对 ×138」 | `stand → interact035/041`：对象进入交互动作，不是击倒 |
| 「击飞 c79 + State=13」 | c79 + `State="hurt_spitout"`（13 字节） |
| 「起身 12→1」 | `interact041 → ""` |
| §4.4 N 为方位角（0..180 度），实现按 `atan2` 下发 | N 是叠加计数，首次恒为 1 |
| 铁律 2「观察者零位移流」 | 位移经 `0x2C` 广播；只是没有 `0x21` 意图帧 |
| 帧族布局 `c56 / c78 / c79 / m18`、击飞浮空时长、击退不换 State | **仍有效** |

2433 分支 `cmd/protocol-probe/control_lease.go` 的 `controlStateFrame` 用
`clientdata.Int32Value(state)` 下发 `State=1/6/12/13`，与同一仓库属性表里 State 的线型
（字符串）不符：客户端会把这 4 字节读成串长度。本分支只有文档、没有这套实现。
